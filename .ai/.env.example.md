# .env.example

> Last updated: 2026-10-12 | Protection: NORMAL

## Purpose

Reference env file for local development. Product vars (APP_URL, DB, auth
providers, AI, email, billing, jobs, observability) plus kit-ops vars.

`TRUSTED_PROXY_COUNT` defaults to 0; set it only for a known reverse-proxy
chain that appends `x-forwarded-for`.

## Database

- `DATABASE_URL` must match `docker-compose.yml`'s `POSTGRES_*` credentials
  (`supastack:supastack` — changed 2026-09-22 from `postgres:postgres`).
  `packages/db/drizzle.config.ts` loads the repo-root `.env`, so
  `pnpm --filter @supastack/db db:migrate` works without exporting anything.
  `tests/local-setup.test.ts` guards the parity.
- Optional commented `POSTGRES_PASSWORD`, `MINIO_ROOT_USER`, and
  `MINIO_ROOT_PASSWORD` Compose overrides retain `supastack` local defaults.
  They are local-only examples; a VPS must use a unique generated Postgres
  password matching `DATABASE_URL` before the initial database volume start.

## Marketing leads additions

- `MARKETING_INBOX` — optional inbox that gets a notification email per
  lead (existing var, first documented 2026-09-21).
- `MARKETING_LEAD_STORE` — `local` | `firestore`; unset keeps lead capture
  email-notify only. `local` writes `.data/marketing-leads.json`
  (gitignored dev state), overridable via `MARKETING_LEAD_STORE_PATH`.
- `FIREBASE_PROJECT_ID` / `FIREBASE_CLIENT_EMAIL` / `FIREBASE_PRIVATE_KEY`
  / `FIRESTORE_DATABASE` — Admin SDK creds required when the store is
  `firestore`; `\n`-escaped PEM accepted.

## Growth additions

- `EARLY_ACCESS_INVITE_ONLY` — `true` | `false` (default `false`; must not
  be left empty — zod enum). When `true`, registration requires a valid
  early-access invite code (`?invite=` cookie or bind); admin method and
  `ADMIN_EMAILS` bypass.

## AI additions

- `OPENROUTER_API_KEY` / `OPENROUTER_APP_NAME` / `OPENROUTER_SITE_URL` —
  required/optional envs for `AI_PROVIDER=openrouter` (model IDs like
  `anthropic/claude-sonnet-4`; app name + site URL become the X-Title and
  HTTP-Referer attribution headers).
- `AGENT_FRAMEWORK` — `ai-sdk` (default) | `mastra` | `langgraph` |
  `openai-agents`; picks the `@supastack/agents` adapter for server-side
  agent runs (workspace tools are shared with `/api/mcp`).

## Billing additions

- `BILLING_PROVIDER` += `paddle` | `dodo` | `paypal`. Per provider:
  `PADDLE_API_KEY` / `PADDLE_PRICE_ID` / `PADDLE_WEBHOOK_SECRET` /
  `PADDLE_ENVIRONMENT` (sandbox|production);
  `DODO_PAYMENTS_API_KEY` / `DODO_PRODUCT_ID` /
  `DODO_PAYMENTS_WEBHOOK_KEY` / `DODO_PAYMENTS_ENVIRONMENT`
  (test_mode|live_mode); `PAYPAL_CLIENT_ID` / `PAYPAL_CLIENT_SECRET` /
  `PAYPAL_PLAN_ID` / `PAYPAL_WEBHOOK_ID` / `PAYPAL_ENVIRONMENT`
  (sandbox|live). Each ships commented `*_PRO` / `*_PRO_YEARLY` /
  `*_LIFETIME` per-plan ids, and a comment names its webhook receiver
  (`/api/billing/webhook/<provider>` + header scheme). Stripe now matches
  that per-plan shape — commented `# STRIPE_PRICE_ID_PRO=` /
  `# STRIPE_PRICE_ID_LIFETIME=` beside the uncommented
  `STRIPE_PRICE_ID_PRO_YEARLY=` (all four read via `process.env` in
  `apps/web/src/product-plans.ts`, not the zod schema).

## Observability additions

- `ALERT_WEBHOOK_URL` — optional HTTPS endpoint beside `SENTRY_DSN` /
  `NEXT_PUBLIC_POSTHOG_*` with a one-line comment. Set →
  `serverConfig.observability.alertWebhookUrl` and
  `serverObservability.alert` POSTs `{text,name,severity,context}` JSON
  (5s timeout, fire-and-forget, one `console.warn` per failed delivery);
  unset/empty → noop alerter. Ships uncommented-empty like the other
  observability vars.

## Analytics additions

- `ANALYTICS_PROVIDER` — `off` (default) | `local` | `plausible` |
  `posthog`; selects the marketing analytics adapter. `local` posts
  consent-gated pageviews/events to `/api/analytics/collect` into the
  `analytics_event` table (summarized on the admin overview); the script
  providers inject their tag only after consent.
- `ANALYTICS_SITE_ID` — required when the provider is `plausible` or
  `posthog` (Plausible `data-domain` / PostHog project key).
- `ANALYTICS_HOST` — optional https URL overriding the script/API origin
  (self-hosted or EU instances; defaults `https://plausible.io` /
  `https://us.i.posthog.com`).

## Mobile/auth-origins additions

- `EXPO_ACCESS_TOKEN` — optional server-only Expo access token; the
  server-side push sender sends `Authorization: Bearer <token>` to the
  Expo push API when set (per-token security, higher rate limits).
  Ships uncommented-empty beside the `EXPO_PUBLIC_*` vars; never a
  public/client config value.
- `MOBILE_ALLOWED_ORIGINS` — comma-separated absolute origins merged into
  Better Auth `trustedOrigins` (`packages/auth` → `createAuthCoreV1Config`)
  for the mobile/desktop shells. Ships uncommented-empty: empty falls back to
  `[APP_URL]` (`allowedOrigins` in `packages/config`), while
  `APP_ENV=production` still requires it — exact non-local HTTPS origins,
  wildcards rejected. Added 2026-10-06 because `docs/agent-setup.md` mandates
  it and the runbook contract forbids vars missing from this inventory.

## Kit-ops additions

- `SUBREPO_{WEB,MOBILE,DESKTOP}_REMOTE` + `SUBREPO_HOME` — optional sync-target overrides for `pnpm sync:subrepos` (defaults derive from origin org; clones stage under `.subrepos/`). One deduplicated commented block at the file tail.
- `SUPASTACK_APP_URL` — URL the Tauri desktop shell loads; runtime env wins
  over the compile-time `option_env!` value, default localhost:3000. Ships
  set once in the Desktop section (the duplicated commented copy at the
  tail was removed).
- `SUPASTACK_DESKTOP_HOTKEY` — global shortcut override (tauri accelerator
  syntax, default `CmdOrCtrl+Shift+Space`). Ships commented once.
- `SUPASTACK_UPDATER_ENDPOINT` + `SUPASTACK_UPDATER_PUBKEY` — commented pair
  for signed desktop updater releases (details in `docs/desktop-updates.md`);
  `check:release-config` requires both-or-neither and emits the
  `plugins.updater` `--config` overlay. The private signing key never lives
  here — CI secrets only.
- `TRUSTED_PROXY_COUNT` — 0–10, default 0; reverse proxies that append
  `x-forwarded-for` in front of the app. Anonymous rate-limit keys take the
  entry that many hops from the right; 0 = trust no entries (shared
  `unknown` bucket). Ships commented beside `RATE_LIMIT_STORE`, which now
  also carries a commented `# NODE_ENV=` (schema var that drives the
  postgres default and counts as production when `APP_ENV` is unset) and a
  corrected failure-mode comment — production limiters pass
  `failClosed: true`, so store outages reject instead of failing open.
